## 3. M1：基础平台

### 目标

建立可长期扩展且可重复构建的技术基线。

### 产出

- Flutter Android/iOS 工程、五项导航、统一主题、路由和 API 客户端。
- Spring Boot 模块化单体、统一错误、认证边界和健康检查。
- MySQL、Redis、Flyway、测试替身和环境配置。
- Web 原型保留并与后端健康检查连通。
- CI 执行后端测试、Flutter 分析与测试、密钥和格式检查。

### 验证与决策

- 使用模块化单体，拒绝无依据的微服务拆分。
- test 与 prod 环境资源和密钥严格隔离。
- 迁移只新增、不回写已发布版本。
- 阶段门禁：构建、基础集成、迁移和安全默认规则通过。

## 4. M2：账户与健康档案

### 产出

- 手机验证码、密码、微信、Apple 登录与统一身份绑定。
- Access/Refresh Token、轮换、设备列表、撤销和退出。
- 七步健康建档、测量历史、偏好、目标、风险问卷和进度恢复。
- 同意版本、健康数据授权、导出和注销流程基础。

### 验证与决策

- 开发验证码仅在 local/test 可用，生产配置强制关闭。
- 所有健康数据查询从认证主体限定用户。
- 高风险问卷命中后不进入普通减脂流程。
- 阶段门禁：认证滥用、用户隔离、档案校验和恢复流程通过。

## 5. M3：核心健康闭环

### 产出

- BMI、BMR、TDEE、营养和安全策略的纯计算模块与规则版本。
- 计划预览、确认、历史、重算、调整、暂停与恢复。
- 今日聚合、下一步建议和模块级失败隔离。
- 饮食库、餐食、营养汇总、饮水和趋势。
- 离线操作队列、幂等键、多设备版本与冲突提示。

### 验证与决策

- 计划预览不修改当前计划，确认或重算生成新版本。
- AI 只解释计算结果，不参与核心数值决策。
- 营养汇总由服务端计算，客户端仅展示和预估。
- 阶段门禁：核心端到端闭环、计算边界和离线恢复通过。

## 6. M4：健康扩展与报告

### 产出

- 手动运动、睡眠记录、目标和趋势。
- Health Connect 与 HealthKit 授权、增量同步、去重和撤回。
- 每日任务、重复、延期、跳过、勿扰和通知状态。
- 日报、周报、月报、数据充分性和 PDF/图片导出。

### 验证与决策

- 拒绝系统健康权限时，手动记录仍完整可用。
- 手动与系统数据冲突不静默合并。
- 数据不足时报告展示缺口，不生成确定性结论。
- 阶段门禁：跨午夜、时区、重复同步和报告追溯通过。

## 7. M5：AI 与商业闭环

### 产出

- 私有图片上传、异步食物识别、候选、置信度与人工确认。
- 免费、Pro、家庭版权益和家庭授权。
- 微信、支付宝、iOS 内购、退款、回调验签和对账。
- 食物、内容、会员、订单、反馈、通知和配置管理后台。

### 验证与决策

- AI 失败可转手动，未确认结果不创建餐食。
- 权益在服务端检查，客户端展示不能替代鉴权。
- 支付回调幂等，订单与权益状态可对账修复。
- 阶段门禁：恶意上传、重复扣费、伪造回调和管理越权测试通过。

## 8. M6：生产交付

### 产出

- Web 品牌、账户、报告、导出、安全和隐私功能。
- 正式隐私政策、用户协议、会员说明和 SDK 清单。
- 国内云、HTTPS、数据库、Redis、对象存储、监控、告警与备份。
- Android/iOS 发布材料、签名流程、灰度、回滚和客服应急机制。

### 验证与决策

- 生产密钥只由密钥服务和流水线注入。
- 完成性能、安全、兼容、无障碍、恢复与回滚演练。
- 严重/高危缺陷为零后才允许 v1.0.0 放行。
- 阶段门禁：最终测试、质量检查、安全评审和验收通过。

## 9. 决策记录

| 编号 | 决策 | 原因 |
|---|---|---|
| ADR-01 | 使用 Flutter 支持 Android/iOS | 减少重复实现，保留平台适配层 |
| ADR-02 | 使用 Spring Boot 模块化单体 | 业务边界清楚，部署与事务更简单 |
| ADR-03 | 核心健康数值使用规则引擎 | 可解释、可重复测试并可版本化 |
| ADR-04 | AI 结果必须人工确认 | 控制误识别对健康记录的影响 |
| ADR-05 | 用户数据以服务端为权威 | 支持多设备、审计、权益和一致性 |
| ADR-06 | 健康平台同步可拒绝 | 保证手动路径和最小权限原则 |

## 10. 最终遗留限制

- 产品不替代医疗服务，风险提示和专业求助入口长期保留。
- 第三方服务可用性受供应商影响，降级和监控必须持续维护。
- 健康算法和食物数据需要随标准与证据更新，变更必须版本化并回归。
- 生产证据需按每次发布重新生成，本文状态不能替代实际流水线记录。
