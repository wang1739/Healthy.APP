# 轻食记 Healthy 项目计划书

文档编号：LB-PLAN-004
版本：1.0
日期：2026-09-07
目标基线：v1.0.0

## 1. 计划目标

本计划将需求规格转化为可管理的阶段、交付物和质量门禁。项目采用短迭代、里程碑验收和主干保护；核心健康、安全与支付能力优先保证正确性，不以压缩测试换取进度。

## 2. 工作分解与里程碑

| 阶段 | 计划周 | 主要范围 | 完成标准 |
|---|---:|---|---|
| M1 基础平台 | W1–W4 | 架构、Flutter 壳、API、数据库、Redis、CI | 环境可重复构建，基础测试通过 |
| M2 账户与档案 | W5–W9 | FR-01、FR-02、FR-15 基础 | 登录、会话、七步建档、风险拦截通过 |
| M3 核心闭环 | W10–W16 | FR-03–FR-06 | 计划、今日、饮食、饮水完整可用 |
| M4 健康扩展 | W17–W21 | FR-07–FR-10 | 运动、睡眠、任务、报告通过验收 |
| M5 商业闭环 | W22–W27 | FR-11、FR-12、FR-14 | AI 确认、权益、支付、后台完成 |
| M6 生产交付 | W28–W32 | FR-13、FR-16、全部 NFR | 合规、安全、压测、恢复、灰度完成 |

## 3. 阶段任务

### M1 基础平台

- 确认模块化单体边界、数据规则和 API 约定。
- 建立 local、test、prod 配置和密钥注入方式。
- 建立 Flutter 主题、路由、状态、API、存储与五项导航。
- 建立 Spring Boot、Flyway、MySQL、Redis、统一错误和健康检查。
- 建立 CI、依赖锁定、制品和基础质量检查。

### M2 账户与档案

- 完成验证码、密码、第三方登录、Token 轮换与设备管理。
- 完成档案、测量、偏好、目标、风险问卷与授权。
- 完成账号注销和隐私同意版本记录的基础流程。
- 执行认证滥用、用户隔离和敏感日志测试。

### M3 核心闭环

- 完成纯函数计划规则、边界和版本化。
- 完成计划预览、确认、调整、暂停与历史。
- 完成今日聚合、饮食、饮水、离线队列与多设备冲突。
- 进行核心闭环端到端测试和规则专家复核。

### M4 健康扩展

- 完成运动、睡眠、任务、通知和手动记录。
- 接入 Health Connect 与 HealthKit，完成权限和同步测试。
- 完成日报、周报、月报和导出。
- 验证时区、跨午夜、重复同步和数据不足场景。

### M5 商业闭环

- 完成私有图片上传、异步 AI 识别和用户确认。
- 完成会员、家庭授权、权益控制、订单和退款。
- 接入微信、支付宝和 iOS 内购沙箱及生产配置。
- 完成管理后台、审计日志、AI 成本和支付对账。

### M6 生产交付

- 完成 Web 用户端、正式协议、SDK 清单和应用市场资料。
- 完成容量、性能、安全、无障碍、兼容和灾备测试。
- 完成域名、HTTPS、备案、监控、告警、备份和运行手册。
- 内测、灰度、指标观察、最终验收和 v1.0.0 发布。

R=执行，A=最终负责，C=协商，I=知会。

|---|---|---|---|---|---|---|---|---|
| 范围与优先级 | A | R | C | I | I | C | C | I |
| 架构与数据 | I | C | A | C | R | C | C | C |
| 健康规则 | C | A | R | C | R | C | C | I |
| App/Web | I | C | A | R | C | C | C | I |
| API/集成 | I | C | A | C | R | C | C | C |
| 测试验收 | C | C | C | C | C | A/R | C | C |
| 安全隐私 | I | C | C | C | C | C | A/R | C |
| 发布运维 | I | I | C | I | C | C | C | A/R |

## 5. 质量门禁

每个里程碑必须满足：需求和设计已评审；代码审查完成；自动化测试通过；数据库迁移可升级；无新增严重/高危问题；文档同步；演示与验收记录可复核。M6 还必须通过压测、渗透测试、恢复演练、支付对账和隐私检查。

## 6. 风险与依赖管理

| 编号 | 负责人 | 触发信号 | 计划动作 |
|---|---|---|---|
| R-01 | 产品/技术 | 规则边界异常或专家异议 | 冻结发布、修正规则、全量回归 |
| R-02 | 安全 | 越权、泄漏或高危扫描项 | 隔离环境、修复、复测和事件评估 |
| R-03 | 后端 | 第三方错误率或超时超阈值 | 启用降级、切换供应商或暂停入口 |
| R-04 | 项目 | 资质/审核未按关键日期完成 | 提前送审，调整非核心发布范围 |
| R-05 | 技术 | 同步冲突和重复率升高 | 加强幂等、版本和冲突交互 |
| R-06 | 客户端 | 健康数据重复或漏同步 | 停止自动合并，修复游标与去重 |
| R-07 | 运维 | P95、错误率、资源持续超阈值 | 扩容、索引、缓存和限流 |
| R-08 | 项目 | 里程碑内新增未评估需求 | 提交变更单，评估范围/时间/成本 |

外部依赖包括短信与开放平台资质、支付商户、Apple 开发者、国内云与域名备案、对象存储、AI 服务、应用市场账号和健康平台真机。

## 7. 沟通与报告

- 每日：开发同步阻塞与高风险事项。
- 每周：范围、燃尽、缺陷、质量指标和风险台账。
- 里程碑：演示、测试摘要、遗留项和放行决策。
- 发布期：变更窗口、负责人、监控、回滚点和事件频道。
- 决策进入仓库文档，聊天结论需转为可追踪记录。

## 8. 变更管理

变更需包含动机、需求编号、用户影响、数据影响、安全隐私影响、工作量、测试和回滚方案。产品、技术、测试共同评估；影响 P0、数据模型、支付、隐私或发布日期的变更由项目负责人批准并更新基线。

## 9. 配置与发布管理

- `main` 始终保持可发布，变更通过短分支和评审合入。
- 使用语义化版本；数据库迁移只前进，不修改已发布脚本。
- test 与 prod 使用独立资源和密钥，制品从同一提交构建。
- 发布采用灰度、监控和自动/人工回滚门槛。
- 发布证据包括提交、制品摘要、迁移、测试、扫描、审批和监控链接。

## 10. 完成定义

需求实现、评审、自动化与必要人工测试、错误与空状态、日志与指标、数据迁移、文档、安全隐私检查全部完成，且不存在阻断缺陷，才可标记完成。
