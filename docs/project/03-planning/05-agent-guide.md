# 轻食记 Healthy Agent 文档

文档编号：LB-DEV-005
版本：1.0
日期：2026-09-07

## 1. 目的

本文供开发者和自动化编码 Agent 在仓库内工作时使用。目标是快速定位代码、遵循项目边界、执行必要验证并避免对健康、安全、隐私和支付产生不可审计的改动。

## 2. 项目原则

- 这是健康生活管理产品，不是医疗诊断系统。
- 核心健康数值由可测试规则产生；生成式 AI 不决定热量、减重速度或风险结论。
- 后端采用模块化单体。没有容量或团队证据时不拆微服务。
- 服务端是身份、权益、营养汇总、订单和同步冲突的最终权威。
- 不伪造第三方集成、生产凭据、测试结果或合规状态。
- 优先使用语言、框架和平台标准能力，避免不必要依赖。

## 3. 仓库结构

```text
Healthy.APP/
├─ backend/             Spring Boot API、迁移和测试
├─ mobile/              Flutter Android/iOS 应用
├─ assets/              Web 静态资源
├─ docs/                设计、计划与项目交付文档
├─ scripts/             本地和 CI 检查脚本
├─ index.html            品牌 Web 入口
├─ nutrition.html        饮食交互原型/功能页
├─ docker-compose.yml    本地 MySQL、Redis 等依赖
└─ README.md             项目入口文档
```

后端按 `auth`、`user`、`profile`、`plan`、`nutrition`、`hydration`、`activity`、`sleep`、`workplan`、`report`、`ai`、`membership`、`notification`、`admin`、`audit` 分包。模块不得直接访问其他模块的数据仓库，应通过应用服务接口协作。

## 4. 开发流程

1. 阅读需求编号、相关设计和现有测试。
2. 检查工作区，保留用户的无关改动。
3. 对数据、安全或接口变更先说明影响与回滚策略。
4. 先补失败测试或可复现步骤，再实现最小变更。
5. 运行针对性测试，再运行项目级检查。
6. 检查差异、密钥、迁移、错误状态和文档。
7. 使用简洁提交信息，禁止把真实 `.env`、证书或构建产物提交。

## 6. 编码约束

### 6.1 后端

- API 使用 `/api/v1`，错误结构保持统一。
- 所有用户资源从认证主体取得 `user_id`，不能信任客户端传入的所有者。
- 输入在服务端校验；列表必须分页并限制页大小。
- 核心写入采用事务，重试任务和支付回调必须幂等。
- 时间、金额和营养值使用明确类型与精度。
- Flyway 已发布迁移不可修改；新增迁移需验证空库和升级路径。
- 日志禁止输出密码、验证码、Token、完整手机号和完整健康档案。

### 6.2 Flutter 与 Web

- 使用公共主题和组件，不散落颜色、字号、间距和圆角。
- 页面必须覆盖加载、空数据、部分数据、失败、离线和重试状态。
- Token 存入安全存储，非敏感偏好才可存普通本地存储。
- 兼顾小屏、横屏、大字体、读屏语义和系统减少动画设置。
- 未经确认的 AI 结果不得写入正式记录。

### 6.3 安全与隐私

- 不自创加密算法；使用经过维护的框架和算法。
- 新增个人信息字段时同步更新目的、保存期、导出和删除流程。
- 新增 SDK 前检查权限、初始化时机、数据共享和用户同意。
- 文件上传验证类型、大小、内容、所有权和生命周期。
- 高风险管理操作需要二次确认、最小权限和审计记录。

## 7. 测试要求

- 健康规则：固定输入输出、上下限、临界值和风险拒绝。
- 认证：验证码滥用、Token 轮换、撤销和跨用户访问。
- 数据：用户隔离、事务、幂等、迁移和并发冲突。
- 客户端：导航、表单、离线、弱网、重启恢复和无障碍。
- 集成：第三方超时、重复回调、验签失败和降级。
- 发布：性能、安全、备份恢复、回滚和监控告警。

修复缺陷必须增加能阻止回归的测试。不得仅通过删除测试、放宽断言或吞掉异常让流水线通过。

## 8. 禁止事项

- 不提交真实密钥、数据库、用户健康数据或支付资料。
- 不绕过身份、权益、风险拦截或支付验签。
- 不直接修改生产数据或已发布迁移。
- 不宣称未执行的测试、审核、真机或生产验证已经通过。
- 不扩大第三方权限或数据收集范围来规避实现问题。
- 不用大规模重构掩盖一个局部需求。

## 9. 完成前检查

- 变更与需求和模块边界一致。
- 测试可复现且通过，新增失败场景已覆盖。
- 无调试开关、敏感日志、空链接和演示数据误导。
- 数据迁移、兼容、监控、回滚和文档影响已处理。
- `git diff --check` 和密钥扫描通过，提交范围只含预期文件。

## 10. Agent 输出要求

完成任务时说明：修改内容、关键决策、验证命令与结果、未验证项、风险和文件位置。遇到缺少凭据、第三方资质、真机或生产权限时，应明确阻塞条件并保留安全降级，不得模拟成功。
