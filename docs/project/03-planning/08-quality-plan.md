# 轻食记 Healthy 项目质量计划书

文档编号：LB-QA-008
版本：1.0
日期：2026-09-07
适用基线：v1.0.0

## 1. 质量目标

确保产品功能正确、健康建议安全、数据隔离可靠、支付一致、隐私权利可执行，并可在生产环境监控、恢复和回滚。

| 目标 | 指标与门槛 |
|---|---|
| 需求完整性 | P0/P1 需求测试覆盖率 100%，追踪关系完整 |
| 缺陷 | 发布时阻断/严重缺陷 0，高优先级缺陷 0 |
| 自动化 | 关键规则、认证、订单、数据隔离和迁移全部自动化覆盖 |
| 安全 | 已知严重/高危漏洞 0，专项安全测试通过 |
| 性能 | 核心读 P95 ≤ 500 ms，核心写 P95 ≤ 800 ms |
| 可用性 | 月度目标 ≥ 99.9%，关键依赖有降级 |
| 恢复 | RPO ≤ 24 小时，RTO ≤ 4 小时 |
| 可访问性 | 核心流程支持大字体、键盘/读屏语义和减少动画 |

## 2. 适用标准

- 需求和验收：本文档集中的 FR、NFR 与 TC 追踪规则。
- 版本与变更：语义化版本、受评审变更和不可变发布证据。
- 安全：OWASP Web/API/Mobile 常见风险、最小权限和安全默认配置。
- 隐私：最小必要、明示同意、健康信息单独同意、用户权利和数据生命周期。
- 工程：自动化构建、版本化迁移、同行评审、可观测性和可恢复发布。

## 4. 质量活动

### 4.1 需求阶段

- 对每项需求检查明确性、可测试性、优先级、风险和数据影响。
- 建立 FR/NFR—测试—验收追踪关系。
- 对健康、隐私、支付和第三方需求进行专项评审。

### 4.2 设计阶段

- 评审模块边界、数据所有权、失败降级、幂等、迁移和回滚。
- 对健康规则建立输入、公式、边界、版本和专家确认记录。
- 建立威胁模型和个人信息数据流图。

### 4.3 开发阶段

- 代码必须通过同行评审、格式/静态检查、单元和集成测试。
- 关键缺陷先建立复现测试，再修复。
- 依赖、密钥、日志、迁移和 API 兼容性纳入流水线。

### 4.4 测试阶段

- 执行功能、端到端、兼容、无障碍、性能、安全和恢复测试。
- 对验证码、越权、健康边界、离线同步、支付和注销重点回归。
- 测试数据使用合成或脱敏数据，生产数据不得复制到普通测试环境。

### 4.5 发布与运行

- 从同一提交生成签名制品，记录摘要和物料清单。
- 采用灰度发布，观察错误率、延迟、登录、支付和核心转化。
- 按阈值自动或人工回滚，事件进入复盘和缺陷流程。

## 5. 评审门禁

| 门禁 | 放行条件 |
|---|---|
| G1 需求基线 | 范围、验收、风险和数据分类通过评审 |
| G2 设计基线 | 架构、规则、威胁模型、迁移与回滚明确 |
| G3 功能完成 | 代码评审和自动化测试通过，无严重缺陷 |
| G4 候选发布 | 全量回归、扫描、压测和兼容测试通过 |
| G5 生产发布 | 合规材料、备份恢复、灰度和审批完整 |

任何 R-01、R-02、R-03、R-04 未受控，或 NFR-01、NFR-02、NFR-06 不满足时不得越过 G5。

## 6. 测试策略

- 单元测试：规则、校验、换算、状态机和序列化。
- 集成测试：数据库迁移、事务、认证、用户隔离、缓存和对象存储。
- Widget/UI 测试：表单、导航、空错状态、离线和可访问性。
- 端到端测试：注册建档、生成计划、每日记录、报告、订阅和注销。
- 非功能测试：容量、性能、稳定、弱网、兼容、安全和恢复。

采用风险优先策略。健康规则、身份、数据隔离和支付状态机的测试深度高于展示性页面。

## 7. 缺陷管理

| 级别 | 定义 | 时限与处理 |
|---|---|---|
| 阻断 | 数据损坏、错误支付、核心流程不可用 | 立即停止发布并修复 |
| 严重 | 越权、高危漏洞、不安全健康建议 | 当日响应，修复复测后放行 |
| 高 | 主要功能错误且无合理绕行 | 当前里程碑关闭 |
| 中 | 局部功能错误且有绕行 | 纳入最近迭代 |
| 低 | 文案、轻微视觉或优化建议 | 排入维护版本 |

缺陷必须包含环境、版本、步骤、预期、实际、证据、严重度、责任人、修复提交和回归结果。

## 8. 度量与报告

每周报告需求变更、构建成功率、自动化结果、缺陷趋势、逃逸缺陷、代码评审时效、安全问题、P95 延迟、错误率和风险状态。指标用于发现系统问题，不用于鼓励删除测试或拆分无意义提交。

## 9. 配置与文档质量

- 发布配置通过环境变量或密钥服务管理，仓库只保留示例。
- 文档与接口、迁移、版本、运行手册同步更新。
- 每份报告标明基线、环境、证据和未验证项。
- 未实际执行的检查不得标记“通过”。

## 10. 质量计划结论

本计划覆盖从需求到运行的质量活动，并为 R-01 至 R-08 设置相应控制。满足全部发布门禁后，v1.0.0 可进入最终验收。
