# 轻食记「睡眠管理」设计规格

## 1. 背景与目标

轻食记已经具备游客浏览、手机号登录、七步健康档案、减脂计划、今日执行中心，以及饮食、饮水和运动记录。健康计划包含睡眠目标，但用户还不能记录实际睡眠、查看睡眠趋势或设置睡前提醒。

本阶段交付账号级、可跨设备同步的手动睡眠记录闭环。用户可以记录夜间睡眠与小睡，系统根据入睡和醒来时间自动计算时长，并保存睡眠质量、影响标签和可选备注。“今日”页面展示同一份服务端权威睡眠数据；手机使用已有本地通知能力提供一组睡前提醒。

## 2. 范围

### 2.1 本期包含

- 手动记录夜间睡眠和午睡/小睡。
- 使用系统日期与时间选择器设置入睡时间和醒来时间。
- 自动计算睡眠时长，不允许客户端单独提交不同的时长。
- 五级睡眠质量：很差、较差、一般、良好、很好。
- 固定的可多选睡眠影响标签和可选备注。
- 编辑和软删除本人睡眠记录。
- 按醒来日期读取当天夜间睡眠、小睡和汇总。
- 最近 7 天平均夜间睡眠、目标达标天数、平均质量和小睡总时长。
- 使用活动健康计划的睡眠目标；无可执行计划时不虚构目标。
- Today 接入真实睡眠摘要和两个页面入口。
- 一组设备本地睡前提醒：提醒时间、重复星期和通知权限状态。
- 游客和未完成档案用户沿用现有渐进式权限闭环。
- 中文页面、按钮、状态、通知和错误提示；新增控件统一使用 6 px 圆角。

### 2.2 本期不包含

- Android Health Connect、iOS HealthKit、手表或第三方平台同步。
- 自动识别入睡、睡眠阶段、心率、血氧、打鼾或呼吸分析。
- 强制唤醒闹钟、声音包、智能唤醒和多套提醒日程。
- 医疗诊断、失眠判断或自动生成治疗建议。
- 月度复杂图表；月度与周期结论由后续报告模块负责。
- 无网络时的离线写入队列。
- 外部健康平台同步表、游标或适配框架；本期只预留记录来源字段。

## 3. 产品规则

### 3.1 用户状态

| 用户状态 | 浏览 | 新增、编辑、删除 | 查看个人统计 | 睡前提醒 |
|---|---|---|---|---|
| 游客 | 可查看示例结构和功能说明 | 点击后进入登录 | 不展示虚构数据 | 不安排 |
| 已登录、档案未完成 | 可查看空状态 | 点击后进入建档 | 提示完成档案 | 不安排 |
| 已登录、档案完成 | 允许 | 允许 | 展示真实数据 | 按本机设置安排 |

完成登录和建档后，应用返回用户原先想使用的睡眠操作。退出登录时回到游客浏览状态，并取消当前账号在该设备上安排的睡眠通知。

### 3.2 页面入口

- 不新增底部导航项，保持现有六项导航不变。
- Today 的“记录睡眠”快捷操作直接进入睡眠记录页。
- Today 的睡眠摘要卡进入睡眠管理页。
- 保存成功后返回睡眠管理页，并同步刷新 Today 睡眠摘要。

### 3.3 记录类型与默认值

- `NIGHT`：夜间睡眠。
- `NAP`：午睡或其他小睡。
- 新增夜间睡眠时，默认醒来时间为当前时间，入睡时间为向前 8 小时。
- 新增小睡时，默认醒来时间为当前时间，入睡时间为向前 30 分钟。
- 默认值只是减少操作的表单草稿，用户必须确认后才保存。

### 3.4 时间、归档与重叠

- 入睡时间必须早于醒来时间。为容忍手机与服务器时钟轻微偏差，醒来时间最多可比服务端当前时间晚 5 分钟，超过时按未来时间拒绝。
- 夜间睡眠允许 30 分钟至 16 小时。
- 小睡允许 5 分钟至 4 小时。
- 按记录发生地时区的醒来日期归档。例如 9 月 9 日 23:30 入睡、9 月 10 日 07:00 醒来，归入 9 月 10 日。
- 保存 UTC 入睡/醒来时间、创建时区和稳定的本地醒来日期；之后设备切换时区不得自动改写历史归档日期。
- 同一用户的未删除睡眠区间不得重叠。
- 每个本地醒来日期最多一条夜间睡眠；用户应编辑原记录进行修正。
- 同一天允许多条互不重叠的小睡。
- 夜间临时醒来使用“夜间醒来”标签表达，本期不拆分多个夜间片段。
- 允许补录历史睡眠，不允许创建未来睡眠。

### 3.5 睡眠质量

- 很差 = 1。
- 较差 = 2。
- 一般 = 3。
- 良好 = 4。
- 很好 = 5。
- 质量为可选项；未选择时显示“未评价”，不阻止快速保存。
- 页面主要展示中文评价，数字只作为内部稳定契约和统计依据。

### 3.6 影响标签与备注

固定标签包括：

- 压力较大 `STRESS`。
- 喝了咖啡 `CAFFEINE`。
- 饮酒 `ALCOHOL`。
- 睡前使用手机 `SCREEN_TIME`。
- 夜间醒来 `NIGHT_AWAKENING`。
- 环境嘈杂 `NOISE`。
- 身体不适 `DISCOMFORT`。

标签可以多选，也可以全部不选。备注可选，去除首尾空白后最多 500 个字符。后续报告可统计标签出现次数，但本期不得据此自动给出医学结论。

### 3.7 睡眠目标

- 只使用当前可执行健康计划的 `sleepHours`，不在睡眠页面维护第二套目标。
- 用户需要调整目标时进入计划页面修改。
- 没有活动计划时只展示真实睡眠数据，并提示“生成计划后可查看目标进度”。
- 计划暂停、需要重新计算或风险阻断时展示对应中文状态，不按正常目标计算达标。
- 小睡不计入夜间睡眠目标，防止白天补觉掩盖长期夜间睡眠不足。

### 3.8 最近 7 天统计

- 统计范围为所选日期及之前 6 个本地醒来日期。
- 平均夜间睡眠只计算有效夜间记录的时长。
- 达标天数只在存在可执行计划目标时计算。
- 平均睡眠质量只计算已评价的夜间睡眠记录。
- 小睡总时长累加该范围内全部有效小睡。
- 少于 3 条夜间睡眠记录时仍显示真实汇总，但标记“记录不足”，不生成趋势性结论。

## 4. 架构

采用“独立睡眠模块 + 服务端权威记录与汇总 + 设备本地提醒”方案。

Spring Boot 新增独立 `sleep` 模块，负责记录、标签、用户隔离、幂等、时间校验、重叠判断、每日汇总、7 天统计和 Today 聚合。Flutter 负责页面交互、最近成功缓存、表单草稿和本地通知调度。服务端响应是睡眠数据和统计的最终权威。

睡前提醒属于设备行为，使用现有 `flutter_local_notifications`、`timezone`、`flutter_timezone` 和 `shared_preferences`，不新增依赖或服务端提醒表。提醒设置按账号保存在当前设备，不承诺跨设备同步。

不复用每日任务表保存睡眠，不把睡眠数据只存在手机本地，也不提前建设健康平台同步框架。现有认证、API 客户端、会话状态、渐进式建档、计划状态、Today 聚合和 Flyway 迁移方式全部复用。

## 5. 数据模型

### 5.1 `sleep_records`

- 不可预测唯一 ID。
- `user_id`。
- `record_type`：`NIGHT` 或 `NAP`。
- `started_at`、`ended_at`：UTC 时间。
- `timezone`：创建或最后修改时间区间时的用户时区。
- `wake_local_date`：按上述时区计算的稳定归档日期。
- `duration_minutes`：由服务端从区间计算并保存。
- `quality_score`：可空，范围 1–5。
- `note`：可空，最多 500 个字符。
- `source`：本期固定为 `MANUAL`。
- `external_source_id`：可空，仅为未来平台同步预留。
- `idempotency_key`：与 `user_id` 组成唯一约束。
- `deleted_at`：软删除时间。
- `created_at`、`updated_at`。

唯一与索引约束覆盖用户幂等键、用户归档日期、记录类型、发生区间和未删除查询。数据库边界约束保护记录类型、时长、质量和备注长度。

### 5.2 `sleep_record_tags`

- `sleep_record_id`。
- `tag_code`：只允许已定义标签代码。
- 两列组成唯一约束，避免同一记录保存重复标签。

标签随睡眠记录软删除结果一同从有效查询中排除。客户端不能提交或查询其他用户 ID。

## 6. API 契约

所有接口位于 `/api/v1` 并要求认证。游客示例由 Flutter 本地结构提供。

- `GET /sleep/days/{date}?timezone=Asia/Shanghai`：返回所选醒来日期的夜间睡眠、小睡、当天汇总和计划状态。
- `GET /sleep/weeks/{date}?timezone=Asia/Shanghai`：返回所选日期及之前 6 天的原始每日点、平均夜间时长、达标天数、平均质量、小睡总时长和数据充分状态。
- `POST /sleep/records`：创建记录；使用 `Idempotency-Key`，返回更新后的日汇总和 7 天汇总。
- `PUT /sleep/records/{id}`：编辑本人记录并重新计算归档日期与时长。
- `DELETE /sleep/records/{id}?timezone=Asia/Shanghai`：软删除本人记录，返回更新后的日汇总和 7 天汇总。

请求只提交类型、开始/结束时间、时区、可选质量、标签代码和备注。客户端不得提交 `durationMinutes`、`wakeLocalDate` 或目标达标结果。

写入失败使用现有统一错误结构：`code`、`message`、`fieldErrors`、`timestamp` 和 `path`。

## 7. Flutter 页面

### 7.1 睡眠管理页

1. 日期导航：前一天、后一天和返回今天。
2. “昨晚睡眠”主卡：夜间时长、目标差值、质量和状态。
3. 最近 7 天摘要：平均夜间时长、达标天数、平均质量、小睡总时长。
4. 简单的每日睡眠时长条形展示，不引入图表库。
5. 当天记录列表：夜间睡眠和小睡按醒来时间倒序，支持编辑和中文删除确认。
6. 主操作按钮：“记录睡眠”。
7. 睡前提醒设置入口。

### 7.2 记录与编辑页

1. 使用两段控件选择“夜间睡眠”或“午睡/小睡”。
2. 使用系统日期和时间选择器设置入睡、醒来时间。
3. 实时显示自动计算的时长和服务端边界提示。
4. 使用五个中文选项设置可选睡眠质量。
5. 使用多选标签记录影响因素。
6. 备注输入默认收起，点击“添加备注”后显示。
7. 底部固定保存按钮，避开键盘和系统手势区域。

### 7.3 页面状态

- 游客浏览引导。
- 档案未完成引导。
- 当天无记录。
- 正常睡眠、目标达标和记录不足。
- 无活动计划、计划暂停、需要重新计算和风险阻断。
- 最近成功缓存，标记“数据可能不是最新”。
- 网络失败、重新加载和保留未提交表单。
- 保存中禁止重复点击；保存成功后刷新睡眠页和 Today。

## 8. 睡前提醒

- 每个账号在当前设备最多保存一组提醒：开关、时间和重复星期。
- 默认关闭；只有用户主动开启时才请求通知权限。
- 时间使用系统时间选择器，重复星期至少选择一天。
- 使用非精确、允许低功耗模式的本地通知，不申请精确闹钟权限。
- 通知文案使用中文且不包含敏感健康详情，例如“该准备休息了，保持规律作息”。
- 通知权限拒绝不影响睡眠记录，页面显示权限状态和“前往系统设置”。
- 设置变化、设备时区变化、应用启动或恢复到前台时按需重新安排。
- 退出登录时取消该账号已安排的睡眠通知；本地偏好可以保留，重新登录后按当前权限恢复安排。
- 通知 ID 由账号摘要和星期稳定生成，不得取消饮水或其他模块的通知。

## 9. 缓存与写入体验

- 按账户和本地归档日期隔离最近成功缓存。
- 日期切换时不得短暂展示另一日期的睡眠记录。
- 网络失败且存在缓存时展示缓存并明确标识；无缓存时显示中文失败状态和“重新加载”。
- 表单提交失败时保留类型、时间、质量、标签和备注；同一次创建重试复用幂等键。
- 本期不做离线新增、编辑或删除队列。
- 页面销毁、账号切换或请求过期后，迟到响应不得更新当前页面。

## 10. Today 集成

Today 聚合接口将睡眠模块由 `COMING_SOON` 替换为真实状态：

- `status`：`READY`、`EMPTY`、`PROFILE_INCOMPLETE`、`NO_PLAN`、`PAUSED`、`NEEDS_RECALCULATION`、`RISK_BLOCKED` 或 `ERROR`。
- `nightDurationMinutes`、`targetMinutes`、`differenceMinutes`。
- `qualityScore`、`qualityLabel`。
- `napDurationMinutes`。
- `hasEnoughTrendData`。

Today 只展示摘要和入口，不实现第二套记录逻辑。睡眠模块失败不得阻止计划、体重、营养、饮水或运动模块返回。

## 11. 视觉与可访问性

- 沿用深绿色、米白色和克制高对比的现有品牌体系。
- 所有新增卡片、按钮、输入框和弹窗圆角统一为 6 px。
- 所有用户可见页面、按钮、状态、通知、确认框和错误提示使用中文。
- 时间通过原生选择器输入，时长自动计算，减少键盘输入。
- 质量和影响因素使用大触控区域的单选/多选控件。
- 备注输入默认收起，避免干扰快速记录主流程。
- 7 天趋势只使用简单条形和文字，不增加图表依赖或过度动画。
- 支持 720×1600、系统大字体、读屏语义、键盘、底部安全区域和减少动画设置。

## 12. 异常与一致性

- 幂等键保证创建请求重复提交只产生一条记录。
- 服务端重新计算时长和醒来日期，并校验类型、质量、标签、备注和时区。
- 重叠检测覆盖夜间与小睡，排除当前编辑记录和已软删除记录。
- 同一归档日期重复夜间记录返回明确中文冲突提示并引导编辑原记录。
- 删除不存在、已删除或不属于当前用户的记录不得泄露数据存在性。
- 编辑或删除后，日汇总、7 天汇总和 Today 必须来自同一权威规则。
- 无可执行计划时目标字段为空，不用零值伪装目标。
- API 返回不得包含内部异常、SQL、用户 ID 或其他账号信息。

## 13. 验收标准

### 13.1 后端

- V7→V8 迁移不改变已有账号、档案、计划、饮食、饮水和运动数据。
- 夜间睡眠、小睡、质量、标签和备注的新增、编辑与软删除正确。
- 时间先后、未来时间、类型时长边界、重叠和每日唯一夜间记录正确。
- 按醒来日期归档、跨午夜、时区和 7 天范围边界测试通过。
- 幂等重试、用户隔离、跨用户访问和不存在记录保护正确。
- 平均夜间时长、达标天数、平均质量、小睡总时长和记录不足状态正确。
- 有计划、无计划、暂停、待重算和风险状态正确。
- Today 睡眠失败时其他模块继续返回。

### 13.2 Flutter

- 游客、未建档、空数据、正常、达标、记录不足、缓存和网络失败状态通过。
- 夜间/小睡切换、默认时间、系统时间选择和自动时长通过。
- 五级质量、影响标签、可选备注、编辑和中文删除确认通过。
- 写入失败保留表单，创建重试不重复记录。
- 账号切换、日期切换和页面销毁后的迟到请求不污染状态。
- 睡前提醒开关、时间、星期、权限允许/拒绝和退出登录取消通过。
- Today 和睡眠页使用同一服务端权威汇总。
- 全部用户文案为中文，新增控件圆角为 6 px。
- `flutter analyze`、全量测试和 Debug APK 构建通过。

### 13.3 Android 模拟器

- 使用 Android API 36 和已完成档案账号完成完整设备触控验收。
- 从 Today 两个入口进入，保存夜间睡眠后验证 Today 立即刷新。
- 验证跨午夜夜间睡眠、小睡、编辑、中文删除确认和历史补录。
- 验证重复夜间记录、区间重叠、未来时间和时长边界拦截。
- 验证质量、全部标签、备注折叠和 7 天趋势。
- 验证睡前提醒时间/星期、通知权限允许与拒绝、退出登录取消。
- 验证游客、未建档、断网缓存和重新加载。
- 完成 720×1600、1.3 倍字体、键盘、安全区域和减少动画冒烟。
- 生成 Debug APK，记录路径、文件大小和 SHA-256。

## 14. 实施组织

本期继续使用三个独立任务并行实施：

1. 后端与数据库：V8、睡眠记录、标签、汇总及 Today 接入。
