# 轻食记前后端分离基础框架设计

日期：2026-09-04

## 目标

在不破坏现有官网和饮食记录功能的前提下，为“轻食记”建立可长期扩展的前后端分离基础框架。前端负责界面与用户交互，Spring Boot 后端负责身份、健康档案、计划、记录、分析和持久化，MySQL 保存用户长期数据。

本阶段只搭建工程基础、运行环境、API 约定和模块边界，不在同一次改动中完成注册登录、健康档案和全部生活计划业务。

## 已确认的产品方向

- 产品面向需要长期使用健康管理工具的普通用户。
- 核心闭环为：登录 → 健康档案 → 个性化计划 → 每日执行 → 数据分析 → 周月复盘 → 调整计划。
- 健康范围包含饮食、运动、饮水、睡眠和健康导向的工作安排。
- 桌面端使用极简图标侧栏，悬停展开并允许固定。
- 手机端使用高度 43px、左右间距 5px 的深色贴边底部导航。
- 手机首页顶部包含最多三张真实摄影轮播，展示饮食、运动和睡眠重点。
- 普通界面元素最大圆角为 6px。

## 仓库结构

现有前端文件先保持在仓库根目录，确保 `http://localhost:4173/` 和已有功能继续工作。后端新增到独立目录：

```text
E:\Healthy
├─ index.html
├─ nutrition.html
├─ *.css / *.js / assets
├─ backend
│  ├─ pom.xml
│  ├─ mvnw / mvnw.cmd
│  ├─ src/main/java/com/lightbite/healthy
│  ├─ src/main/resources
│  └─ src/test
├─ docker-compose.yml
├─ .env.example
└─ docs
```

等前端页面增加到三个以上时，再通过独立迁移将前端移动到 `frontend/`，避免本次基础框架搭建同时改变现有页面路径。

## 技术基线

- Java：17，与本机 Temurin 17.0.19 环境一致。
- Spring Boot：4.1.1。
- 构建工具：Maven，工程同时提供 Maven Wrapper，避免依赖全局 Maven 版本。
- 数据库：MySQL 8.4 容器，不连接本机已有 MySQL 5.7。
- 数据迁移：Flyway，所有表结构通过版本化 SQL 创建。
- 数据访问：Spring Data JPA。
- 安全框架：Spring Security；框架阶段仅建立安全边界，注册登录在后续独立模块实现。
- 输入校验：Jakarta Validation。
- 运行检查：Spring Boot Actuator。
- 测试：JUnit 5、Spring Boot Test、Testcontainers MySQL。

## 后端模块边界

采用按业务能力分包，而不是按 controller/service/repository 全局分层：

```text
com.lightbite.healthy
├─ common       通用响应、异常、时间和基础配置
├─ security     安全配置与未来身份上下文
├─ user         用户账号
├─ profile      健康档案与健康目标
├─ plan         个性化生活计划编排
├─ nutrition    饮食记录与营养分析
├─ activity     运动计划与运动记录
├─ hydration    饮水目标与打卡
├─ sleep        睡眠目标与记录
├─ workplan     健康导向的工作安排
└─ report       周报、月报与趋势汇总
```

每个业务包内部自行包含 API、应用服务、领域对象和数据访问代码。模块之间通过明确的服务接口协作，禁止直接访问其他模块的数据库仓库。

## 第一阶段框架能力

### 启动与配置

- 后端默认监听 `8080`。
- 配置区分 `local`、`test` 和 `prod`。
- 数据库地址、用户名、密码和签名密钥只从环境变量读取。
- 仓库提供 `.env.example`，不提交真实密码。
- 使用 UTF-8 编译、日志和 API 编码，保证中文数据稳定。

### 数据库容器

- 根目录 `docker-compose.yml` 只启动一个 MySQL 8.4 服务。
- 数据保存在命名卷中，重启容器不丢失。
- 容器提供健康检查，Spring Boot 在数据库可用后连接。
- 默认仅面向本机开发端口，不开放生产环境配置。

### API 约定

- 所有业务接口统一使用 `/api/v1` 前缀。
- JSON 字段使用 camelCase。
- 时间戳使用 ISO 8601，并明确时区。
- 成功响应直接返回资源或分页结构。
- 错误响应统一包含 `code`、`message`、`fieldErrors`、`timestamp` 和 `path`。
- 框架提供 `GET /api/v1/system/ping`，用于验证前后端连接。
- Actuator 只公开必要的健康检查端点。

### 跨域与前端连接

- 本地开发允许 `http://localhost:4173` 和 `http://127.0.0.1:4173` 调用 API。
- 允许的来源通过环境配置管理，不使用任意来源通配符。
- 前端新增单一 API 配置入口，默认指向 `http://localhost:8080/api/v1`。
- 框架阶段只让现有前端完成 ping 健康检查，不把本地饮食记录立即迁移到数据库。

### 安全基础

- 除 ping 和健康检查外，默认接口需要认证。
- 禁止在日志中输出密码、令牌和完整健康档案。
- 密码未来使用自适应单向散列，不保存明文。
- 健康档案属于敏感数据，后续所有查询必须按当前用户隔离。
- 生产配置不提供默认密码，不允许自动降级到开发密钥。

## 后续业务实施顺序

框架完成后按以下独立子项目推进：

1. 用户注册、登录、退出和令牌续期。
2. 健康档案建立、修改和隐私授权。
3. 根据档案计算基础目标并生成首份生活计划。
4. 将现有饮食记录从 localStorage 迁移为登录用户云端数据。
5. 运动、饮水、睡眠和工作计划模块。
6. 今日总览、完成度、提醒和个性化轮播。
7. 周报、月报和长期趋势。

每个子项目单独确认规则和验收标准，避免把健康计算、身份安全和界面开发混在一个不可验证的大改动中。

## 验收标准

1. 现有官网与 `nutrition.html` 的访问和交互不受影响。
2. `docker compose up -d` 能启动健康状态正常的 MySQL 8.4。
3. Maven Wrapper 能在 Java 17 下完成测试与打包。
4. Spring Boot 能使用环境变量连接数据库并成功执行 Flyway 初始迁移。
5. `GET /api/v1/system/ping` 返回包含服务状态和时间的 JSON。
6. `GET /actuator/health` 返回健康状态，但不暴露敏感配置。
7. 本地 4173 前端可以成功调用 ping 接口，其他来源不在默认允许列表中。
8. 校验失败和未知路径返回统一 JSON 错误结构。
9. 测试覆盖应用启动、ping、跨域、安全默认规则和数据库迁移。
10. 仓库不包含真实数据库密码、令牌或其他密钥。

## 本阶段不包含

- 正式注册登录页面和完整身份业务。
- 真实用户表、健康档案表和健康分析算法。
- 将现有 localStorage 饮食记录自动上传数据库。
- 消息推送、短信、邮件和第三方登录。
- 生产服务器、域名、HTTPS 和正式部署流水线。

这些内容在基础框架通过验收后，按后续子项目逐项实现。
