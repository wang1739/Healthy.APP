# 轻食记「运动管理」设计规格

## 1. 背景与目标

轻食记已经具备游客浏览、手机号登录、七步健康档案、减脂计划、今日执行中心、云端饮食记录和饮水管理。运动目标目前只存在于健康计划中，用户还不能记录实际运动、查看当天消耗或了解每周计划完成情况。

本阶段交付账号级、可跨设备同步的手动运动记录闭环。用户可以选择常用或自定义运动，记录时长与强度，由系统根据运动类型、档案体重和时长估算消耗热量，并允许用户修改最终热量。“今日”页面展示同一份服务端权威统计，不使用虚构运动数据。

## 2. 范围

### 2.1 本期包含

- 按用户本地日期读取运动记录和当天汇总。
- 记录运动类型、发生时间、持续时长、强度和消耗热量。
- 提供低、中、高三档强度。
- 提供 15、30、45、60 分钟快捷时长及手动分钟输入。
- 内置常用运动类型，并支持搜索。
- 允许用户创建仅自己可见的自定义运动类型。
- 根据运动类型强度系数、最新体重和时长自动估算热量。
- 允许用户修改最终热量，并保留系统估算值。
- 编辑和删除本人运动记录。
- 展示当天运动次数、累计时长和累计消耗。
- 展示周一至周日的计划完成天数和分钟数。
- 今日执行中心接入真实运动状态和快捷入口。
- 游客和未完成档案用户沿用现有渐进式权限闭环。
- 中文页面、按钮、状态、确认框和错误提示；新增控件统一使用 6 px 圆角。

### 2.2 本期不包含

- Android Health Connect、iOS HealthKit、手表或第三方平台同步。
- 实时运动计时、GPS 轨迹、配速、心率和训练课程。
- 好友排行、挑战、勋章或社交分享。
- 基于运动记录自动重写健康计划。
- 医疗级热量测量或运动处方。
- 无网络时的离线写入队列。网络失败时保留用户填写内容并允许重试。
- 单独的同步游标表或外部平台适配框架；数据结构只预留必要来源字段。

## 3. 产品规则

### 3.1 用户状态

| 用户状态 | 浏览 | 新增、编辑、删除 | 查看个人统计 |
|---|---|---|---|
| 游客 | 可查看示例结构和功能说明 | 点击后进入登录 | 不展示虚构个人数据 |
| 已登录、档案未完成 | 可查看空状态 | 点击后进入建档 | 提示完成档案 |
| 已登录、档案完成 | 允许 | 允许 | 展示服务端真实数据 |

登录和建档完成后，应用返回用户原先想使用的运动操作。退出登录后回到游客浏览状态。

### 3.2 页面入口

- 不新增第七个底部导航项，保持现有六项导航不变。
- “今日”页的“记录运动”快捷操作进入运动记录页。
- “今日”页的运动统计卡片进入运动管理页。
- 保存成功后返回运动管理页，并同步刷新今日运动卡片。

### 3.3 内置运动类型

首批内置类型包括：步行、跑步、骑行、游泳、跳绳、力量训练、瑜伽、羽毛球、篮球、足球、健身操、爬山、椭圆机和划船机。

每个内置类型配置低、中、高三档强度系数。系数属于服务端版本化基础数据，客户端不得自行维护另一套计算表。

### 3.4 自定义运动

- 用户输入自定义运动名称，并选择一种最相似的内置运动。
- 自定义运动继承相似运动的三档强度系数，不要求用户填写专业参数。
- 自定义类型只对创建者可见，可搜索并重复使用。
- 名称去除首尾空白后不能为空；同一用户不可创建规范化后重名的自定义类型。
- 被历史记录引用的自定义类型不得物理删除；本期不提供删除自定义类型入口。

### 3.5 时长、强度与发生时间

- 强度只能选择低、中、高。
- 快捷时长为 15、30、45、60 分钟，也允许键盘输入整数分钟。
- 单次运动时长允许 1–1440 分钟。
- 发生时间默认当前用户本地时间，可通过原生日期和时间选择器修改。
- 不允许创建或修改为未来时间，允许补录历史运动。

### 3.6 热量估算

采用可解释的 MET 估算方式：

`估算热量（kcal） = 强度对应 MET × 体重（kg） × 时长（小时）`

- 使用记录发生时可获得的最新有效体重；若无后续历史体重选择能力，则使用当前档案有效体重。
- 结果四舍五入为整数 kcal，并在界面标注“估算值”。
- 保存记录时存储体重快照、MET 快照和计算版本，后续体重或基础系数变化不得改写历史结果。
- 用户可修改最终热量；修改后同时保留系统估算值，并标记为“已手动修改”。
- 用户可以恢复系统估算值。
- 最终热量允许 0–10000 kcal。该数据仅用于一般健康管理，不代表医疗测量结果。

### 3.7 周计划进度

- 每周按用户时区的周一至周日统计。
- 有活动健康计划时，使用计划中的 `exerciseDays` 和 `exerciseMinutes` 作为目标。
- 运动天数按当天至少存在一条有效运动记录计算，同一天多条记录只计一天。
- 周分钟数为本周所有有效运动记录时长之和。
- 无活动计划时只展示真实累计数据，并提示“生成计划后可查看目标进度”，不虚构默认目标。
- 计划暂停、风险阻断或需要重新计算时，展示对应中文状态，不把目标显示为正常可执行状态。

## 4. 架构

采用“独立运动模块 + 服务端权威计算与汇总”方案。

Spring Boot 新增独立 `activity` 模块，负责运动类型、记录、热量估算、用户隔离、幂等、每日汇总、周计划进度和 Today 聚合。Flutter 负责页面交互、表单预览、最近成功缓存和权限引导。客户端可以即时预览估算值，但保存响应中的服务端结果是最终权威值。

不复用每日任务表保存运动，不将业务数据仅存本地，也不新增外部健康平台同步框架。现有认证、API 客户端、会话状态、渐进式建档、计划状态、Today 聚合和数据库迁移方式全部复用。

## 5. 数据模型

### 5.1 `activity_types`

- 不可预测唯一 ID。
- `owner_user_id`：系统类型为空，自定义类型为创建者。
- `name`、`normalized_name`。
- `category`：稳定的服务端分类值。
- `low_met`、`medium_met`、`high_met`。
- `reference_type_id`：自定义类型所参考的系统类型。
- `type_scope`：`SYSTEM` 或 `USER`。
- `active`。
- `created_at`、`updated_at`。

系统类型由数据库迁移写入。唯一约束分别保护系统规范化名称和同一用户的自定义规范化名称。

### 5.2 `activity_records`

- 不可预测唯一 ID。
- `user_id`。
- `activity_type_id`。
- `activity_name_snapshot`。
- `intensity`：`LOW`、`MEDIUM` 或 `HIGH`。
- `duration_minutes`。
- `occurred_at`：UTC 时间。
- `timezone`：创建或修改时的用户时区。
- `weight_kg_snapshot`。
- `met_snapshot`。
- `calculation_version`。
- `estimated_kcal`。
- `final_kcal`。
- `calorie_source`：`ESTIMATED` 或 `USER_OVERRIDE`。
- `source`：本期固定为 `MANUAL`。
- `external_source_id`：可空，仅为未来平台同步预留。
- `idempotency_key`：与 `user_id` 组成唯一约束。
- `deleted_at`：软删除时间。
- `created_at`、`updated_at`。

索引覆盖用户、发生时间和未删除查询。客户端不能提交或查询其他用户 ID。

## 6. API 契约

所有接口位于 `/api/v1` 并要求认证。游客示例由 Flutter 本地静态结构提供，不开放匿名个人数据接口。

- `GET /activity/types?query=`：返回系统类型和当前用户自定义类型；支持中文名称搜索。
- `POST /activity/types/custom`：创建自定义类型，提交名称和参考系统类型 ID。
- `GET /activity/days/{date}`：返回日期、记录、次数、分钟、热量、页面状态和缓存版本信息。
- `GET /activity/weeks/{date}`：返回该日期所在周范围、实际天数/分钟/热量、计划目标及计划状态。
- `POST /activity/records`：创建记录；使用 `Idempotency-Key`，返回服务端权威日汇总和周汇总。
- `PUT /activity/records/{id}`：编辑本人记录，重新计算估算值；仅当请求明确提供最终热量时保存人工覆盖。
- `DELETE /activity/records/{id}`：软删除本人记录，返回更新后的日汇总和周汇总。

日期查询和写入必须携带有效用户时区。写入失败复用现有统一错误结构：`code`、`message`、`fieldErrors`、`timestamp` 和 `path`。

## 7. Flutter 页面

### 7.1 运动管理页

1. 页面标题与日期导航：前一天、后一天和返回今天。
2. 本周进度卡：实际运动天数、实际分钟、计划目标和状态。
3. 当天汇总：运动次数、累计分钟和累计消耗热量。
4. 当天记录列表：按发生时间倒序，支持编辑和中文删除确认。
5. 主操作按钮：“记录运动”。

### 7.2 记录与编辑页

1. 搜索并选择运动类型。
2. 找不到时创建自定义运动，并选择最相似的内置运动。
3. 使用三段控件选择低、中、高强度。
4. 使用 15、30、45、60 分钟快捷按钮或整数输入框设置时长。
5. 使用系统日期与时间选择器设置发生时间。
6. 实时展示预计消耗热量。
7. 默认收起手动热量输入；点击“修改”后展开，并提供“恢复估算值”。
8. 底部固定保存按钮，避开系统手势和键盘安全区域。

编辑页允许修改类型、强度、时长、发生时间和最终热量。修改记录时服务端重新保存对应快照，不影响其他历史记录。

### 7.3 页面状态

- 游客浏览引导。
- 档案未完成引导。
- 当天无记录。
- 正常记录和周目标完成。
- 无活动计划。
- 计划暂停、风险阻断或需要重新计算。
- 最近成功缓存，标记“数据可能不是最新”。
- 网络失败、重新加载和保留未提交表单。
- 保存中禁止重复点击；保存成功后刷新运动页和 Today。

## 8. 缓存与写入体验

- 按账户和本地日期隔离最近成功缓存，退出或切换账号不得显示上一账号数据。
- 日期切换时不得短暂展示另一日期的统计。
- 网络失败且存在缓存时展示缓存并明确标识；无缓存时显示中文失败状态和“重新加载”。
- 表单提交失败时保留全部输入，同一次重试复用幂等键。
- 本期不做离线新增、编辑或删除队列，避免恢复联网后产生重复或乱序写入。
- 页面销毁、账号切换或请求过期后，迟到响应不得更新当前页面。

## 9. Today 集成

Today 聚合接口将运动模块由 `COMING_SOON` 替换为真实状态：

- `status`：`READY`、`EMPTY`、`PROFILE_INCOMPLETE`、`NO_PLAN`、`PAUSED`、`NEEDS_RECALCULATION`、`RISK_BLOCKED` 或 `ERROR`。
- `todayDurationMinutes`、`todayKcal`、`todayRecordCount`。
- `weekExerciseDays`、`weekDurationMinutes`。
- `targetExerciseDays`、`targetDurationMinutes`：无可执行计划时为空。

Today 只展示摘要和入口，不实现第二套记录逻辑。运动模块失败不得阻止计划、体重、营养或饮水模块返回。

## 10. 视觉与交互规范

- 沿用深绿色、米白色和克制高对比的现有品牌体系。
- 所有新增卡片、按钮、输入框和弹窗圆角统一为 6 px。
- 不使用装饰性过强的渐变或大面积动画。
- 重要数据优先展示，最多使用简单进度条，不堆叠复杂图表。
- 所有用户可见页面、按钮、状态、确认框和错误提示使用中文。
- 支持窄屏、系统大字体、键盘输入、返回键和减少动画设置。
- 达成周目标时使用克制的绿色完成状态，不播放强制庆祝动画。

## 11. 异常与一致性

- 幂等键保证创建请求重复提交只产生一条记录。
- 服务端重新校验运动类型归属、发生时间、时长、强度和热量范围。
- 自定义类型只可引用有效系统类型，不接受其他用户的类型 ID。
- 删除不存在、已删除或不属于当前用户的记录不得泄露数据存在性。
- 编辑和删除后，日汇总、周汇总和 Today 必须来自同一权威计算规则。
- 计划不存在或不可执行时目标字段为空，不用零值伪装目标。
- API 返回不得包含内部异常、SQL、用户 ID 或其他账号信息。

## 12. 验收标准

### 12.1 后端

- 数据库迁移不改变已有账号、档案、计划、饮食和饮水数据。
- 系统运动种子数据、中文搜索、自定义类型和规范化重名校验正确。
- 低、中、高强度计算、取整、体重快照、MET 快照和人工覆盖正确。
- 新增、重复重试、编辑、删除、日汇总和周汇总正确。
- 最新有效体重选择、无体重异常、未来时间和边界值处理正确。
- 用户隔离、软删除、时区、午夜和周一/周日边界测试通过。
- 有计划、无计划、暂停、风险阻断和需要重新计算状态正确。
- Today 运动失败时其他模块继续返回。

### 12.2 Flutter

- 游客、未建档、空数据、正常、完成、无计划、缓存和网络失败状态通过。
- 运动搜索、自定义类型、三档强度、快捷/手动时长和时间选择通过。
- 自动估算、手动修改、恢复估算、编辑和删除通过。
- 写入失败保留表单，重试不重复创建。
- Today 和运动页使用同一服务端权威汇总。
- 账号切换、跨日期和页面销毁后的迟到请求不会污染状态。
- 全部用户文案为中文，新增控件圆角为 6 px。
- `flutter analyze`、全量测试和 Debug APK 构建通过。

### 12.3 Android 模拟器

- 使用 Android API 36 模拟器和已完成档案账号完成设备触控验收。
- 从 Today 快捷入口进入，记录内置运动并验证 Today 立即刷新。
- 搜索和创建自定义运动，之后可再次搜索使用。
- 分别验证三档强度、四种快捷时长和键盘手动输入。
- 验证热量自动估算、手动修改、恢复估算、编辑和中文删除确认。
- 验证历史补录、未来时间拦截、日期切换和周进度。
- 验证游客、未建档、断网缓存与重试。
- 完成 720×1600、1.3 倍字体、键盘、安全区域和减少动画冒烟。
- 生成 Debug APK，记录路径、文件大小和 SHA-256。

## 13. 实施组织

本期继续使用三个独立任务并行实施：

1. 后端与数据库：运动类型、记录、计算、汇总及 Today 接入。
2. Flutter：运动页面、表单、状态管理、缓存和 Today 入口。
3. QA/集成：先建立独立验收矩阵，再合并候选、修复契约问题并完成模拟器触控验收。

三个任务均不得直接推送 `main`。QA 形成唯一最终候选，由主任务复核后合并和推送。
