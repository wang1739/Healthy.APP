# 轻食记「今日执行中心」第一版设计规格

日期：2026-09-08

状态：已确认，待实施

## 1. 背景与目标

减脂计划已经能够根据用户健康档案生成、确认、调整、暂停和恢复。下一阶段需要把已生效计划转化为用户每天打开 App 即可理解的行动入口。

第一版采用“真实计划总览与快捷入口”路线：只展示现有系统能够提供的真实数据，不提前创建简易打卡表，也不使用虚构完成率。饮食、饮水、运动、睡眠和任务模块以后完成时，继续接入同一个聚合接口。

目标：

- 建立稳定、可扩展的今日聚合接口。
- 让不同账户状态的用户看到符合权限和数据完整度的首页。
- 展示当前计划目标、最新体重、下一步建议和后续记录入口。
- 单个数据模块异常时，其他模块仍可展示。
- 保持全中文界面、克制高级的健康品牌风格和 6px 主圆角。

## 2. 首版范围

### 2.1 本期实现

- 新增 `GET /api/v1/today?date=YYYY-MM-DD`。
- 聚合当前计划和最新体重。
- 为营养、饮水、运动、睡眠和任务预留稳定的模块状态。
- 改造 Flutter“今日”页，覆盖游客、未建档、无计划、计划已生效、部分失败和整体断网状态。
- 增加本地高清健康生活照片轮播。
- 增加下拉刷新、上次成功内容保留和中文错误提示。
- 增加后端与 Flutter 自动化测试。

### 2.2 本期不实现

- 饮食、饮水、运动、睡眠和任务的真实记录增删改。
- 为首页单独建立打卡或完成记录表。
- 健康评分、连续打卡、完成率和趋势。
- 基于缺失记录推导的个性化建议。
- 远程轮播内容管理、推送、提醒和后台配置。

这些功能分别在后续业务模块中实现，避免产生重复数据和迁移负担。

## 3. 用户状态与页面行为

| 用户状态 | 今日页行为 | 受限操作行为 |
|---|---|---|
| 游客 | 展示产品能力和不含虚构数值的预览 | 提示登录并完成健康档案，保留原目标功能 |
| 已登录未建档 | 展示“完善健康档案”主行动 | 进入建档，完成后返回原目标功能 |
| 已建档、无计划 | 展示档案最新体重和“生成减脂计划” | 进入计划预览与确认流程 |
| 计划待确认 | 展示“继续确认计划” | 进入计划页继续确认 |
| 计划已生效 | 展示真实目标、当前周数和最新体重 | 可查看计划；记录入口说明后续模块状态 |
| 计划已暂停 | 明确显示暂停状态 | 进入计划页恢复或调整 |
| 风险拦截 | 不展示普通减脂目标 | 提示咨询医生或注册营养师 |

游客不请求私人今日数据。所有私人聚合数据均要求有效登录身份。

## 4. 首页信息架构

页面自上而下排列：

1. 问候与日期：根据本地时间显示“早上好”“下午好”或“晚上好”，显示当天日期及计划周数。
2. 健康生活轮播：使用打包在 App 内的高清真实健康生活照片，支持自动轮播、左右滑动和页码指示，离线可显示。
3. 今日核心目标：突出目标热量、减脂计划状态和当前周数，点击进入计划页。
4. 执行卡片：饮食、饮水、运动、睡眠和体重。目标取自真实计划；尚未接入实际记录的卡片显示“记录功能待接入”。
5. 下一步建议：只根据真实账户、档案和计划状态生成确定性行动。
6. 快捷操作：记录饮食、饮水、运动和睡眠。模块未上线时显示中文说明，不进入空白页面。

健康评分、连续打卡和完成率在真实记录模块上线前不显示。

## 5. 视觉与可用性

- 延续浅色画布、深绿色品牌色、薄边框和高信息密度。
- 卡片、按钮、轮播图和弹层主圆角统一为 6px。
- 不使用大面积胶囊形控件和无意义装饰。
- 轮播图片上的文字必须有足够对比度，并提供语义标签。
- 支持大字体、读屏语义、系统减少动画设置和窄屏布局。
- 轮播自动播放不能阻止用户手动滑动；开启减少动画后停止自动播放。
- 所有功能、状态和错误文案使用中文；`Android`、`iPhone` 等固有设备名称保持原样。

## 6. 后端接口

### 6.1 请求

```http
GET /api/v1/today?date=2026-09-08
Authorization: Bearer <access-token>
```

- `date` 使用 ISO 8601 本地日期格式 `YYYY-MM-DD`。
- App 传入设备当前本地日期。
- 日期格式错误时返回统一中文校验错误。
- 用户身份只从认证主体获取，客户端不传 `userId`。

### 6.2 响应示例

```json
{
  "date": "2026-09-08",
  "plan": {
    "status": "READY",
    "currentWeek": 1,
    "targetKcal": 1470,
    "proteinG": 110,
    "carbsG": 155,
    "fatG": 45,
    "waterMl": 1900,
    "exerciseDays": 4,
    "exerciseMinutes": 35,
    "sleepHours": 8
  },
  "weight": {
    "status": "READY",
    "valueKg": 62.5,
    "measuredAt": "2026-09-07T08:30:00Z"
  },
  "nutrition": { "status": "COMING_SOON" },
  "hydration": { "status": "COMING_SOON" },
  "activity": { "status": "COMING_SOON" },
  "sleep": { "status": "COMING_SOON" },
  "tasks": { "status": "COMING_SOON" },
  "nextAction": {
    "type": "VIEW_PLAN",
    "title": "查看今日目标"
  }
}
```

### 6.3 模块状态

- `READY`：模块有可展示的真实数据。
- `EMPTY`：模块已经可用，但当前用户或日期没有数据。
- `COMING_SOON`：模块尚未实现。
- `ERROR`：模块本次读取失败。

模块响应保留独立状态，后续接入真实记录时无需破坏接口结构。

### 6.4 数据来源与降级

- 计划目标复用现有 `PlanService` 当前计划结果，不复制计划公式。
- 体重读取当前用户最近一条身体测量记录。
- 计划与体重独立加载并独立捕获异常。
- 单模块失败返回该模块的 `ERROR`，聚合接口仍返回其他可用模块。
- 首版不缓存、不新增数据库表、不引入消息队列或新依赖。

## 7. 下一步建议规则

建议为规则生成，不调用 AI：

| 条件 | `type` | 中文标题 |
|---|---|---|
| 档案未完成 | `COMPLETE_PROFILE` | 完善健康档案 |
| 档案完成但无计划 | `CREATE_PLAN` | 生成减脂计划 |
| 存在待确认计划 | `CONFIRM_PLAN` | 继续确认计划 |
| 计划已暂停 | `RESUME_PLAN` | 查看暂停的计划 |
| 计划已生效 | `VIEW_PLAN` | 查看今日目标 |
| 风险拦截 | `VIEW_RISK_GUIDANCE` | 查看健康建议 |

后续记录模块接入后，可以在保持这些基础状态的前提下增加真正的数据驱动建议。

计划预览目前只保存在 Flutter 的 `PlanController` 内存中，不写入数据库。因此
`CONFIRM_PLAN` 由客户端在仍持有预览时覆盖显示；后端聚合接口不持久化或猜测待确认状态。
今日页展示的目标数值仍只使用聚合接口中的已生效计划数据。

## 8. Flutter 数据流

1. “今日”页根据会话状态决定是否请求私人接口。
2. 已登录用户通过 Riverpod 控制器加载指定日期的聚合数据。
3. 首次加载显示骨架或明确加载状态。
4. 请求成功后保存最近一次成功响应。
5. 下拉刷新重新请求相同本地日期。
6. 刷新失败时保留上次成功内容，并显示“数据可能不是最新”。
7. 完全没有可用缓存时显示错误空状态和“重新加载”。
8. App 从后台恢复或检测到本地日期变化时，切换到新日期并重新加载。

快捷入口继续使用现有权限闭环。未完成档案时进入登录或建档；完成档案后，对尚未上线的记录模块显示“该记录功能将在后续阶段接入”。

## 9. 错误与空状态

- 网络不可用：`网络连接失败，请稍后重试`。
- 后端不可用：`服务暂时不可用，请稍后重试`。
- 刷新失败但有旧数据：`刷新失败，当前内容可能不是最新`。
- 无当前计划：`生成计划后，这里会显示你的每日目标`。
- 模块未上线：`记录功能待接入`。
- 单模块失败：`该项数据暂时无法加载`。

错误信息不泄露服务器堆栈、数据库内容、Token 或内部标识。
