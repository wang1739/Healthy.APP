# 轻食记「饮水管理」设计规格

## 1. 背景与目标

轻食记已经具备游客浏览、手机号登录、七步健康档案、减脂计划、今日执行中心和云端饮食记录。饮水目标目前只存在于健康计划中，用户还不能记录实际饮水、查看进度或设置提醒。

本阶段交付账号级、可跨设备同步的饮水记录闭环。用户可以快速记录饮水、删除误记录、调整默认杯量和每日目标，并通过手机本地通知获得提醒。“今日”页面展示真实饮水进度，不使用虚构完成量。

## 2. 范围

### 2.1 本期包含

- 按用户本地日期读取饮水记录和汇总。
- 默认一键记录 250 ml。
- 提供 100、200、250、300、500 ml 常用容量和 1–3000 ml 自定义容量。
- 删除饮水记录并即时更新汇总。
- 设置每日目标、默认杯量、提醒开关、提醒时间范围、提醒间隔和勿扰时段。
- 优先采用活动健康计划的饮水目标；无计划时使用 2000 ml 默认值。
- 用户手动修改目标后以用户设置为准，后续计划变化不静默覆盖。
- Flutter 使用 Android/iOS 本地通知提醒。
- 达成目标后取消当天剩余提醒；删除记录导致重新低于目标时恢复后续提醒。
- 今日执行中心接入真实饮水状态。
- 游客和未完成档案用户沿用现有渐进式权限闭环。
- 中文页面、按钮、状态、通知和错误提示；新增控件统一使用 6 px 圆角。

### 2.2 本期不包含

- 服务端推送、Firebase Cloud Messaging 或 APNs 设备令牌。
- 智能饮水算法和基于天气、运动量的动态目标。
- 好友打卡、排行榜或社交分享。
- 咖啡、茶、酒等复杂饮品折算分类。
- 饮水记录编辑。容量错误时删除原记录后重新添加。
- 无网络时的离线写入队列。网络失败时保留最近成功缓存并允许重新操作。

## 3. 产品规则

### 3.1 用户状态

| 用户状态 | 浏览 | 记录与删除 | 修改设置 | 提醒 |
|---|---|---|---|---|
| 游客 | 可查看页面结构和引导 | 点击后进入登录 | 点击后进入登录 | 不安排 |
| 已登录、档案未完成 | 可查看空状态 | 点击后进入建档 | 点击后进入建档 | 不安排 |
| 已登录、档案完成 | 允许 | 允许 | 允许 | 按授权和设置安排 |

完成登录和建档后，应用返回用户原先想使用的饮水操作。

### 3.2 目标优先级

1. 用户已经保存的手动目标。
2. 当前活动健康计划的饮水目标。
3. 系统默认 2000 ml。

首次读取计划目标时可保存其来源和计划版本。若活动计划后来改变且用户存在手动目标，应用提示“计划目标已更新”，由用户决定是否采用；后端不得静默覆盖手动设置。

每日目标必须在 500–6000 ml 范围内，并按 50 ml 调整。该范围仅用于一般健康记录，不替代医疗建议。

### 3.3 杯量与记录

- 默认杯量为 250 ml，允许设置为 50–2000 ml。
- 常用快捷容量固定为 100、200、250、300、500 ml。
- 单次记录容量为 1–3000 ml。
- 修改默认杯量只影响之后的新记录，不修改历史记录。
- 记录保存实际发生时间和当时容量快照。
- 当天记录按发生时间倒序展示。
- 删除采用软删除并在服务端重新计算汇总。

### 3.4 日期与时区

- 服务端以 UTC 保存实际发生时间。
- 客户端提交用户 IANA 时区或固定时区偏移，后端按用户本地日期查询和汇总。
- 日期切换、午夜、夏令时和时区变化不得导致同一记录重复或丢失。
- 不允许创建未来时间的记录；历史日期允许补录。

## 4. 架构

采用“云端权威记录 + 手机本地通知”方案。

Spring Boot 新增独立 `hydration` 模块，负责设置、记录、汇总、用户隔离、幂等和 Today 聚合。Flutter 负责页面交互、最近成功缓存、即时预览以及本地通知调度。通知调度不依赖后端常驻任务。

不新增服务端组件，不引入 Redis、消息队列或推送平台。现有认证、API 客户端、会话状态、Today 聚合和数据库迁移方式全部复用。

## 5. 数据模型

### 5.1 `hydration_settings`

- `user_id`：用户唯一约束。
- `daily_target_ml`：可空；为空时使用计划或系统默认值。
- `default_cup_ml`：默认 250。
- `reminder_enabled`。
- `reminder_start_time`、`reminder_end_time`。
- `reminder_interval_minutes`。
- `quiet_start_time`、`quiet_end_time`：可空，支持跨午夜。
- `target_source`：`USER`、`PLAN` 或 `DEFAULT`。
- `source_plan_version`：可空。
- `version`：乐观并发版本。
- `created_at`、`updated_at`。

### 5.2 `hydration_entries`

- 不可预测唯一 ID。
- `user_id`。
- `amount_ml`。
- `occurred_at`：UTC 时间。
- `timezone`：创建时的用户时区。
- `source`：`QUICK`、`PRESET` 或 `CUSTOM`。
- `idempotency_key`：与 `user_id` 组成唯一约束。
- `deleted_at`：软删除时间。
- `created_at`、`updated_at`。

索引覆盖用户、发生时间和未删除查询。客户端不能提交或查询其他用户 ID。

## 6. API 契约

所有接口位于 `/api/v1` 并要求认证。

- `GET /hydration/days/{date}`：返回日期、设置、目标来源、记录、总饮水量、剩余量、完成比例和页面状态。
- `POST /hydration/entries`：创建记录；使用 `Idempotency-Key`，返回服务端权威日汇总。
- `DELETE /hydration/entries/{id}`：软删除本人记录，返回更新后的日汇总。
- `GET /hydration/settings`：返回有效设置及目标来源。
- `PUT /hydration/settings`：完整更新设置，使用版本字段避免静默覆盖。
- `POST /hydration/settings/adopt-plan-target`：明确采用当前活动计划目标并清除手动覆盖。

写入失败使用现有统一错误结构：`code`、`message`、`fieldErrors`、`timestamp` 和 `path`。

## 7. Flutter 页面

### 7.1 页面结构

1. 日期导航：前一天、后一天和返回今天。
2. 进度区：已饮用量、有效目标、剩余量和完成进度。
3. 快捷记录：主按钮显示当前默认杯量，例如“+250 ml”。
4. 容量选择：100、200、250、300、500 ml 及自定义输入。
5. 当日记录：按时间倒序，支持中文删除确认。
6. 设置入口：目标、默认杯量、提醒时间范围、间隔、勿扰和权限状态。

### 7.2 页面状态

- 游客引导。
- 档案未完成引导。
- 当日空记录。
- 正常数据和目标完成。
- 无活动计划但使用默认或手动目标。
- 计划目标更新待采用。
- 最近成功缓存，标记“数据可能不是最新”。
- 网络失败和重新加载。
- 通知未授权及前往系统设置。

### 7.3 写入体验

点击快捷容量后客户端可以先展示预计进度，但服务端响应是最终权威值。提交失败时撤回预计结果，保留所选容量并显示“重新添加”。同一次重试复用幂等键，避免重复记录。

## 8. 本地通知

- 使用 Flutter 当前支持的原生本地通知方案，不建设服务端推送。
- 用户开启提醒时请求系统通知权限；拒绝权限不影响记录功能。
- 用户设置开始时间、结束时间和提醒间隔。
- 通知不得落在勿扰时段。
- 设置变化、日期变化、登录状态变化、目标达成或重新低于目标时重新调度。
- 达成目标后取消当天尚未触发的提醒。
- 退出登录时取消该账号安排的提醒。
- 通知文案使用中文，不在锁屏文案中展示敏感健康详情。

## 9. Today 集成

Today 聚合接口新增真实饮水模块：

- `status`：`READY`、`EMPTY`、`PROFILE_INCOMPLETE`、`ERROR`。
- `consumedMl`、`targetMl`、`remainingMl`、`progress`。
- 快捷操作进入饮水页，不在 Today 内实现第二套记录逻辑。

饮水模块失败不得阻止计划、体重或营养模块返回。游客继续由 Flutter 本地状态展示引导。

## 10. 异常与一致性

- 幂等键保证重复提交只创建一条记录。
- 设置版本冲突返回明确中文刷新提示，不做最后写入者静默覆盖。
- 删除不存在、已删除或不属于当前用户的记录不得泄露数据存在性。
- 网络失败时只显示最近成功缓存，并明确标识缓存状态。
- 未缓存日期失败时显示“网络连接失败，请稍后重试”和“重新加载”。
- API 返回值不得包含内部异常、SQL、用户 ID 或其他账号信息。

## 11. 验收标准

### 11.1 后端

- V5→V6 迁移不改变已有账号、档案、计划和饮食数据。
- 容量、目标、杯量、时间范围和间隔边界通过。
- 新增、重复重试、删除、每日汇总和目标优先级正确。
- 用户隔离、软删除和版本冲突正确。
- 默认杯量变化不改写历史记录。
- 日期、午夜和时区测试通过。
- Today 饮水失败时其他模块继续返回。

### 11.2 Flutter

- 游客、未建档、空数据、正常、达标、缓存、网络失败和权限拒绝状态通过。
- 快捷杯量、自定义容量、删除、日期切换和设置保存通过。
- 写入失败撤回预计进度，重试不重复创建。
- Today 和饮水页使用同一服务端权威汇总。
- 全部用户文案为中文，新增控件圆角为 6 px。
- `flutter analyze`、全量测试和 Debug APK 构建通过。

### 11.3 Android 模拟器

- 登录并使用已完成档案账号。
- 250 ml 快捷新增、预设容量、自定义容量和删除。
- 修改默认杯量后历史记录保持原容量。
- 修改目标及采用计划目标。
- 通知权限允许和拒绝路径。
- 设置提醒后存在系统计划任务；达标后取消剩余提醒。
- 日期切换、断网缓存、720×1600 和 1.3 倍字体冒烟。

## 12. 实施组织

本期继续使用三个独立任务：

1. 后端与数据库：V6、饮水 API、汇总及 Today 接入。
2. Flutter：饮水页面、设置、本地通知和状态管理。
3. QA/集成：先建立独立验收矩阵，再合并候选、修复契约问题并完成模拟器触控验收。

三个任务均不得直接推送 `main`。QA 形成唯一最终候选，由主任务复核后合并和推送。
