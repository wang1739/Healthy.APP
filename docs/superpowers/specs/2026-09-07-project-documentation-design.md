# 轻食记项目交付文档体系设计

日期：2026-09-07  
状态：已确认

## 目标

为“轻食记 Healthy”建立一套内容规范、事实口径一致且适合阅读的软件项目交付文档。文档覆盖立项、可行性、需求、计划、执行跟踪、质量、测试和验收全过程，并提交至 `wang1739/Healthy.APP` 私有仓库的 `main` 分支。

## 编写口径

- 产品按规划功能全部完成、具备正式验收条件的最终形态描述。
- 产品范围统一包含品牌 Web、Flutter Android/iOS App、Spring Boot API、MySQL、Redis、私有对象存储、管理后台及生产运维能力。
- 核心业务统一为账户与健康档案、个性健康计划、饮食、饮水、运动、睡眠、工作与生活任务、健康报告、AI 食物识别、会员家庭与支付。
- 目标市场为中国大陆；核心健康数值由可测试规则计算，AI 只负责识别、解释和文字建议。
- 测试、评审与验收报告采用“最终交付基线”口径，列明通过条件、证据位置和结果摘要；不把当前仓库中尚不存在的运行记录冒充为已执行证据。
- 文档中的版本、日期、角色、里程碑、风险等级、质量阈值和验收标准保持一致。

## 文档内容设计

1. 项目建议书：项目背景、问题、目标、范围、价值、资源、风险和立项结论。
2. 可行性分析报告：技术、经济、运营、合规和进度可行性及结论。
3. 需求规格说明书：角色、功能需求、数据规则、接口、非功能需求和验收追踪。
4. 项目计划书：工作分解、里程碑、人员职责、依赖、沟通和变更管理。
5. Agent 文档：仓库结构、开发约束、命令、完成定义、安全边界和协作规则。
6. 项目开发日志：按阶段记录目标、产出、验证、决策和遗留事项。
7. 版本更新日志：采用语义化版本和 Keep a Changelog 风格记录正式版本。
8. 项目质量计划书：质量目标、评审门禁、测试策略、指标和缺陷管理。
9. 项目质量检查报告：对需求、设计、代码、测试、发布资料和追踪矩阵给出检查结论。
10. 代码评审报告：按模块总结正确性、可维护性、性能、测试和待满足的证据要求。
11. 安全评审报告：覆盖认证授权、隐私、上传、支付、依赖、日志、基础设施和应急响应。
12. README：说明最终产品、架构、目录、环境配置、启动、测试、部署和文档入口。
13. 测试用例与测试报告：包含测试环境、功能与非功能用例、预期结果、最终基线结果及证据字段。
14. 项目验收报告：范围核对、验收标准、交付物、遗留限制、签署条件和结论。

## 一致性与可追踪性

- 为主要需求分配 `FR-*`、`NFR-*` 编号，并在测试和验收文档中引用。
- 为风险分配统一编号，在项目建议书、计划和质量文档中复用。
- 统一发布基线为 `v1.0.0`，文档日期为 2026-09-07。
- 统一项目角色为项目负责人、产品负责人、技术负责人、客户端、后端、测试、安全与运维；不虚构个人姓名。
- 统一状态用语为“通过”“有条件通过”“不通过”“待提供证据”，避免含义重叠。

## 质量验证

提交前执行以下检查：

1. 14 项文档逐项对应且索引链接有效。
2. 扫描 `TODO`、`TBD`、空章节和无解释占位符。
3. 检查版本、日期、项目名称、模块名和需求编号一致性。
4. 检查 Markdown 标题层级、表格和相对链接。
5. 执行 `git diff --check`，确保无空白错误。
6. 确认提交只包含本次文档，不包含密钥、环境文件或无关资产。
