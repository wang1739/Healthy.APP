# 减脂计划 QA 验收与契约审查

依据：`docs/superpowers/specs/2026-09-08-fat-loss-plan-design.md`

本文档是独立验收清单，不补写业务实现。验收以合并后的 `codex/fat-loss-qa` 为准。

## 一、规格中尚未定义的契约

以下项目必须由后端实现给出唯一答案，并与 Flutter 一致；否则不建议合入 `main`。

1. 八个计划端点的请求体、响应体、HTTP 状态和稳定错误码。
2. `GET /plans/current` 无计划时的明确空状态结构。
3. `GET /plans/history` 的页数/条数参数、默认值、上限和排序。
4. 调整、重算的期望版本字段以及旧版本冲突的响应。
5. 跨用户按 ID 操作统一返回 `404` 还是 `403`（建议不泄露资源存在性）。
6. “待重算”如何持久化。当前数据模型只列出 `ACTIVE / PAUSED`，没有 stale 字段或对应状态。
7. 重复确认、暂停、恢复的幂等或冲突语义。
8. 目标日期建议的起算日、时区、天数/周数向上取整规则。

## 二、计算边界

### 阻断性歧义

规格要求“当前体重每周变化不超过 1%”，但第 5.3 节目标热量公式未包含该下限。最终规则至少应同时满足：

```text
target_kcal >= TDEE - 750
target_kcal >= TDEE - weight_kg * 0.01 * 7700 / 7
target_kcal >= BMR
target_kcal >= metabolic_basis_safe_floor
```

安全校验必须使用舍入前数值，展示才使用统一舍入值。

### 必测边界

| 类型 | 输入/边界 | 期望 |
| --- | --- | --- |
| 年龄 | 计算日前一天、当天、后一天生日 | 周岁无偏差，18 岁边界稳定 |
| BMI | 舍入前略低/等于/略高于 18.5 | 阻断依赖舍入前值 |
| 目标 BMI | 舍入前略低/等于/略高于 18.5 | 低于 18.5 阻断，不因展示舍入误判 |
| 代谢依据 | `MALE` / `FEMALE` 同一其他输入 | BMR 差 166 kcal，展示性别不被替换 |
| 活动系数 | 1.20 / 1.375 / 1.55 / 1.725 | TDEE 使用版本化常量 |
| 热量下限 | BMR、1500/1200、最大 750 缺口的交叉点 | 取最保守的最大下限 |
| 周变化 | 恰好 1% 与略超 1% | 略超时提高目标热量 |
| 热量调整 | 50 kcal 步长，上/下界内外 | 非步长或越界拒绝，不写库 |
| 饮水 | 1500/3500 ml 及相邻的 100 ml 步长 | 边界可接受，越界/非步长拒绝 |
| 运动 | 0/7 天，30 分钟步长 | 边界可接受，越界/非步长拒绝 |
| 睡眠 | 7.0/9.0 小时，0.5 步长 | 边界可接受，越界/非步长拒绝 |
| 确定性 | 相同快照、调整和 `FAT_LOSS_V1` | 逐字段相同（实体 ID/时间戳除外） |
| 日期 | 过去、当天、安全日期前后一天 | 无效日期阻断；过早日期只返回建议日期，不放大缺口 |

## 三、接口与状态验收

| 用例 | 必须验证 |
| --- | --- |
| 预览 | 不写 `health_plans`/`health_plan_versions`；不接受 BMI/BMR/TDEE/营养结果 |
| 预览到确认期间修改档案 | 确认结果使用最新档案重算，不信任旧预览 |
| 确认 | 同一用户唯一当前计划，首版为 1，返回可重新查询的权威结果 |
| 查询当前 | 有计划返回当前版本；无计划返回正常空状态，非异常 |
| 调整 | 合法调整新增版本；营养克数重算；记录原因；历史只读 |
| 非法调整 | 事务回滚，计划和版本数均不变 |
| 并发调整 | 两个基于同一旧版本的请求最多一个成功，另一个冲突 |
| 档案关键变化 | 旧计划不覆盖，当前查询显示待重算 |
| 重算 | 基于当前档案新增版本，清除待重算标记 |
| 暂停/恢复 | 状态转换受校验；暂停期间不供给“今日”目标；恢复不补造数据 |
| 历史 | 只返回当前用户版本摘要，有稳定排序与条数上限 |
| 失败响应 | 稳定错误码 + 中文说明，不包含 SQL、堆栈或内部类名 |

## 四、用户隔离与信息安全

1. 为用户 A/B 各创建计划，A 对 B 的查询、调整、重算、暂停、恢复全部失败，B 的计划、版本数、时间戳不变。
2. Controller/Service 的用户 ID 只来自认证主体，请求体中任何 `userId` 均不能改变作用用户。
3. 日志不记录完整健康档案、token 或计划输入快照。
4. 返回文案标注“估算”和 `FAT_LOSS_V1`，不表述为诊断、治疗或处方。
5. 扫描仓库中的私钥、token、口令、真实服务 URL 和可识别个人健康数据。

## 五、Flutter 端到端验收

1. 游客操作计划时按“登录 → 完成档案 → 回到计划预览”闭环；示例数值明确标记示例。
2. 其他性别显示且强制选择代谢依据，保存后不改变展示性别。
3. 覆盖无计划、预览、执行中、待重算、暂停、风险和网络失败七种状态。
4. 档案安全完成时进入预览；风险阻断时不请求预览。
5. 确认、调整、重算、暂停、恢复都有加载、成功、失败反馈；保存失败不更新本地成功状态。
6. 网络失败不清空本次运行已加载计划；重启后不把示例/过期数据当当前计划。
7. 调整控件仅提供规格允许的范围和步长；服务端仍独立校验。
8. 页面符合摘要优先顺序，内容卡圆角为 6px，关键数值有中文单位、估算说明和规则版本。
